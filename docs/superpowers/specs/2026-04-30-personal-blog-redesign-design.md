# GitHub 博客个人归档画廊重构设计

日期：2026-04-30

## 背景

当前博客基于 Jekyll 和 `jekyll-theme-chirpy`，内容结构包括 `_posts`、`_tabs`、`_config.yml` 和少量图片资产。目标不是迁移技术栈，而是在保留 Markdown 文章、分类、标签、GitHub Pages 构建方式的基础上，重做主要主题层，让站点从默认 Chirpy 风格转为更有辨识度的个人博客。

参考站点 `https://100t.xiaomimimo.com/` 提供的可复用视觉语言是：强对比、等宽字体、编号索引、细线分隔、克制的交互入口。最终方向不强调“安全”或任何单一领域，而是定位为个人归档。

## 已确认方向

- 技术路径：自定义 Jekyll 主题层，保留现有 Jekyll 内容和 GitHub Pages 工作流。
- 视觉方向：归档画廊。米白背景为主，黑色只用于文字、边线、代码块和必要反差。
- 首页索引：不使用大面积黑色面板。只保留两行轻量命令行文本：

```text
$ tail -f latest.log
writing, learning, wandering_
```

- 站点定位：个人博客，承载文章、想法、复盘和长期记录，不绑定某个专题领域。

## 目标

1. 首页第一屏呈现个人归档气质，而不是营销页或技术专题站。
2. 最新文章、归档、标签、关于页使用统一的编号索引和细线系统。
3. 文章页优先保证长文阅读体验，使用米白正文背景和清晰的代码块样式。
4. 重构应尽量保留现有文章 permalink、分类、标签和图片路径。
5. 移动端布局不能溢出，导航、文章索引、目录都要自然降级为单列。

## 非目标

- 不迁移到 Astro、Vite、Next.js 等新框架。
- 不重写文章内容。
- 不新增评论系统、搜索服务、统计系统或后端功能。
- 不复制参考站点的品牌元素、活动倒计时、表单流程或大面积动态背景。

## 信息架构

### 首页

首页改为个人归档入口：

- 顶部导航：`AFK'S BLOG`、`POSTS`、`ARCHIVE`、`ABOUT`。
- Hero：`WRITING ARCHIVE` 小标题、主标题 `A small archive of days.`、一段中文说明。
- 轻量索引：两行命令行文本，使用上下细线承接上下内容。
- 最新文章：编号列表，展示标题和日期。
- 页面入口：Archive、Tags、About 三个入口，以细线区块呈现。

### 文章页

文章页以米白正文为主：

- 标题区展示文章标题、日期、分类、标签。
- 正文保持较宽松行距，避免 Chirpy 默认卡片感。
- 代码块使用黑底或深色块，和正文形成清晰区分。
- TOC 在桌面端作为侧栏或右侧索引；移动端收起或移动到正文前。
- 上一篇/下一篇使用编号或线框导航。

### 归档、分类、标签页

这些页面统一成索引目录：

- 年份、分类、标签作为等宽小标题。
- 文章列表使用编号、标题、日期和细分隔线。
- 避免卡片堆叠，优先扫读效率。

### 关于页

关于页保持简短：

- 一段个人说明。
- 写作状态或当前关注。
- GitHub/email 等链接。
- 视觉上和首页同一套米白、细线、等宽标题系统。

## 视觉系统

### 色彩

- 主背景：米白 `#f6f3ec` 或接近色。
- 主文字：黑色 `#000000`。
- 次级文字：灰褐色 `#686258`、`#948e83`。
- 强调色：克制橙色，类似 `#d88a2d`。
- 深色块：只用于代码块、少量交互状态，不在首页使用大面积黑色面板。

### 字体

- 标题：系统 sans-serif，字重偏高，保持简洁。
- 索引、导航、元信息：Menlo/Monaco/Consolas 等等宽字体。
- 正文：系统中文字体优先，保证中文阅读舒适。

### 组件

- 顶部导航：细线底边、等宽小字。
- 文章列表：编号 + 标题 + 日期三列，移动端日期换行。
- 入口区块：三列线框，移动端堆叠。
- 代码块：深色背景、清晰内边距、横向滚动保护。
- 链接和按钮：线框或下划线，不使用圆角卡片。

## 技术架构

继续使用 Jekyll。通过添加本地主题文件覆盖 Chirpy 的主要布局，而不是修改 gem 内部文件。

预期新增或覆盖的文件：

- `_layouts/default.html`：站点基础骨架。
- `_layouts/home.html`：首页归档画廊布局。
- `_layouts/post.html`：文章页布局。
- `_layouts/page.html`：通用页面布局。
- `_includes/site-header.html`：顶部导航。
- `_includes/post-index.html`：编号文章列表。
- `_includes/site-footer.html`：底部信息。
- `assets/css/personal-archive.scss`：主样式入口。
- `assets/js/personal-archive.js`：只放必要增强，例如移动端导航或轻量滚动状态。

保留 `_config.yml` 中的站点标题、头像、社交信息、`site.posts`、分类、标签和 permalink 配置。必要时调整 `description`，但不破坏现有文章 URL。

## 数据流

- 首页从 `site.posts` 读取最新文章，按日期倒序生成编号列表。
- 归档页按年份分组读取 `site.posts`。
- 分类页和标签页沿用 Jekyll Archives 或现有集合输出。
- 文章页读取 front matter 中的 `title`、`date`、`categories`、`tags`，缺失时使用安全默认展示。
- 图片继续使用现有 Markdown 路径和 `images/` 资产，不做批量迁移。

## 空状态与异常处理

- 无文章时：首页展示简短空状态，不渲染空列表边框。
- 无标签/分类时：对应元信息区域隐藏，不显示空符号。
- 标题过长时：文章列表允许换行，日期移动到下一行或隐藏到次级行。
- 图片过宽时：正文图片最大宽度为 100%，保持比例。
- 代码过长时：代码块横向滚动，不撑破页面。
- JS 禁用时：页面仍可导航和阅读，动态效果不是核心功能。

## 响应式设计

- 桌面端：内容最大宽度约 1100px，首页可使用两到三列索引区块。
- 平板端：保留两列或切换到单列，避免行宽过窄。
- 手机端：顶部导航压缩，Hero 字号降低，文章列表变成编号 + 标题 + 日期分行。
- 不使用依赖视口宽度持续缩放的正文文字，避免移动端失控。

## 测试计划

1. 本地构建：`bundle exec jekyll build`。
2. 链接检查：沿用现有 GitHub Actions 的 `htmlproofer` 设置。
3. 浏览器检查：首页、文章页、归档页、标签页、关于页。
4. 视口检查：桌面、平板、手机宽度。
5. 内容回归：确认现有文章 URL、图片、分类、标签仍能访问。
6. 无 JS 检查：核心导航和阅读功能可用。

## 实施边界

第一轮实现只做主题层和页面结构，不引入外部前端框架。若构建环境因为本机 Ruby 依赖损坏无法运行，需记录本地限制，并优先保证代码在 GitHub Actions 的 Ruby 3 环境中可构建。
